# 双信号 MCS-mask80：1690→5070 独立训练源最小控制结果审计

日期：2026-11-01。评价等级：单训练 seed、同一 Validation 与 Development 源的开发证据。Final Test 未读取。本轮只新增一个 MCS-mask80 训练，不改 Coset、物理参数、SNR 定义或模型结构。

## 一、直接结论

**增加独立训练源改善了当前模型的独立源分类指标，但没有解决泛化失败和类别塌缩。**5070 源模型相对旧1690 源模型，Validation 逐路 ModAcc 由 13.03% 提至 23.80%，PairExact 由 2.42% 提至 5.24%；Development 分别由 14.08% 提至 22.23%、1.75% 提至 4.28%。两份独立源 split 同向提高，Macro-F1 也提高。然而 Development APSK32 Recall 仅 **0.70%**，比旧模型的 4.55% 更低；PSK8 和 QAM256 Recall 也下降，绝对 PairExact 仍只有 4.28%。**本轮停止条件已触发：不直接扩大至16900源，不恢复Full/MCS双臂机制主线。**

## 二、数据、初始化及资源门禁

- 原训练 H5 的1690源、每源11档原噪声视图逐字节保留；仅在 `train_append5070` 独立命名空间追加3380源。原 Validation 338源和 Development 338源未变。P0门禁检查四 split UID、干净源哈希、11档噪声种子集合互斥，源级干净波形重算哈希，逐点抽查Full→历史Coset映射，全部PASS。训练前后门禁 JSON **完全一致**，四个 H5 的 SHA-256也一致。原train/Validation/Development哈希分别为 `be0a6113…`、`61f95699…`、`bd403ae6…`；新增H5为`0bf92a36…`。
- 旧模型真实训练配置为 seed **271070**、DualV6(80,13)、batch256、Adam lr1e−3、weight decay1e−4、label smoothing0.1、200 epoch、Validation PairExact优先且Macro-F1并列选点。新模型沿用同一seed与训练规则，随机初始化，不加载旧checkpoint。新训练脚本按旧初始化代码路径重放两次，逐张量 `state_dict` 相等，初值摘要 `f32629f7e23ad1587b68a066f031e263f594af06040251cca60ef8406422603c`。**旧训练当时没有保存初始权重快照，故不能在事后对旧运行的实际初值做逐字节证明**；这是可复现初始化路径的验证，不应写成已直接比较两个历史文件。
- 启动前四卡各约48GiB可用显存，主机 available约114GiB，磁盘约257GiB可用。唯一新模型在GPU3运行完成200 epoch，无OOM；旧数据、旧checkpoint及历史16900源结果未覆盖。
- 旧训练每epoch 73个优化步、200 epoch共14600步；新训练每epoch 218步、200 epoch共43600步。第67 epoch保存等更新次数诊断checkpoint（14606步），**未用Development选点**。新模型最终最佳Validation checkpoint在epoch **8**（1744步），旧模型在epoch **37**（约2701步）。因此最终所选checkpoint的改善不能简单说成“训练更多更新步”，但不同源数量改变每epoch样本覆盖和优化轨迹，源数量与训练过程的混杂仍存在。

## 三、同源独立集的固定评价

|split / 指标|旧1690源模型|新5070源模型|变化|
|---|---:|---:|---:|
|Validation逐路ModAcc|13.03%|23.80%|+10.77 pp|
|Validation PairExact|2.42%|5.24%|+2.82 pp|
|Validation Macro-F1|0.1265|0.2168|+0.0903|
|Development逐路ModAcc|14.08%|22.23%|+8.15 pp|
|Development PairExact|1.75%|4.28%|+2.53 pp|
|Development Macro-F1|0.1356|0.2013|+0.0657|
|旧训练源原视图 PairExact|99.99%|48.85%|—|

同一 Development 视图中，PairExact `新正确/旧错误` 为144个、反向50个；Validation为180/75。每个独立源有11档相关视图，这些计数不当成独立源样本。完整11档曲线和13类指标见 `evaluation_5070_vs_1690_20261101/`。例如Development −2 dB逐路ModAcc从16.42%→21.45%，+10 dB从16.27%→26.78%；曲线改善但高SNR仍很低。

新最佳checkpoint对旧训练源的 PairExact为48.85%，独立Validation为5.24%，训练/验证差仍很大。新模型最佳epoch的训练损失1.466、Validation损失2.451；epoch200分别约0.557、2.412，晚期过拟合仍明显。最佳epoch早至8说明增加源并未自动形成稳定可泛化的双路判别器。

## 四、−2 dB原视图／同源新噪声／独立Validation

三列使用同一−2 dB目标功率与标签；前两列为**同一1690个旧训练源**，仅AWGN不同；第三列为独立Validation的338源，不与训练源一一对应，不能把三列当成逐样本三重配对。旧、新模型在各列都使用完全相同的输入源集合与噪声规则。

|模型|旧训练源原噪声 PairExact / ModAcc|旧训练源新AWGN PairExact / ModAcc|独立Validation PairExact / ModAcc|
|---|---:|---:|---:|
|旧1690|99.94% / 99.97%|30.18% / 51.80%|2.96% / 14.64%|
|新5070|44.67% / 66.48%|22.19% / 44.70%|4.44% / 23.82%|

新模型原视图与新噪声的绝对PairExact差为22.48 pp，旧模型为69.76 pp；**这主要可能反映新最佳checkpoint对旧训练视图也远未拟合到100%**，不能据较小差距断言模型已摆脱噪声视图记忆。新模型同源新噪声的绝对PairExact反而低于旧模型（22.19% vs30.18%）；独立源虽提升至4.44%，仍远低于同源新噪声22.19%。因此固定含噪视图和源特征记忆/泛化不足仍存在，且两者无法由这一次单档检验完全拆分。

## 五、类别塌缩与停止判断

Development每类有572次真值（两路、11档合计）。

|类别Recall|旧1690|新5070|判断|
|---|---:|---:|---|
|APSK32|4.55%|**0.70%**|严重塌缩恶化|
|PSK8|23.08%|15.38%|退化|
|PSK16|15.73%|39.16%|改善但预测过多|
|QAM64|3.32%|11.54%|改善但仍很低|
|QAM256|23.08%|17.66%|退化|

新模型预测PSK16共1270次，而真值支持572次；APSK32仅预测63次。总体改善是类别间不均衡的交换，**没有通过“重点类无严重退化/无近零Recall”门槛**。应停止直接扩至16900源；先做只读核对：旧16通道MCS输入与当前80通道稀疏输入、Res1dNet31与DualV6双头、标签频率排序及训练时序的差异。此核对仅解释失败来源，不在本轮训练另一模型。

## 六、回答研究问题与主线恢复条件

1. **独立源数量增加是否改善泛化？**在这一个seed和固定协议下，Validation与Development的ModAcc、PairExact、Macro-F1均提高，支持“源规模是影响因素”；不支持“源规模是唯一原因”。
2. **噪声视图记忆是否减轻？**无法确证。新最佳checkpoint对原训练视图拟合程度更低，同源换噪声仍显著下降，且绝对新噪声成绩低于旧模型。
3. **类别塌缩是否改善？**局部改善、整体未解决；APSK32接近零Recall并恶化。
4. **更新次数混杂？**总训练更新次数从14600增至43600；但选中checkpoint分别约2701与1744步。等更新次数checkpoint已保存但未选模，也未用于Development主结论。训练轨迹混杂仍需如实保留。
5. **是否扩至16900源？**目前**不应直接扩**，先核对16/80通道与网络/标签差异，避免盲目堆数据。
6. **能否恢复Full/MCS双信号主线？**尚不能。要求独立Validation和Development的两路准确率、PairExact、Macro-F1达到可信水平，关键13类无近零Recall，再冻结同源共噪声Full/MCS双臂比较。当前4.28% PairExact和APSK32 0.70% Recall不满足。
