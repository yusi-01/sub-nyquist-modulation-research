# 双信号单种子泛化失败归因：只读诊断

日期：2026-11-01。证据等级：**冻结最佳 checkpoint 的 train/Validation 只读评价 + 既有 Development 分析**。未重新训练、未读 Final Test、未改变 Coset、SNR、标签或网络。本诊断不是对新训练方案的预注册验证。

## 结论

**当前首要瓶颈是独立源泛化失败。**Full80 和 MCS-mask80 的最佳 Validation checkpoint 在训练源上分别达到 **100.00% / 99.99% PairExact**，在独立 Validation 源上仅 **3.95% / 2.42%**，Development 为 **2.58% / 1.75%**。模型能记住 1690 个训练源在 11 档噪声下的两路调制标签，却未学到足以泛化的判别规则。因此现在既不能据 Full−MCS 小差值宣称低 SNR 物理优势，也不能据 η 分层非单调否定 Oracle 线性噪声放大。**η→CNN 错误路线在当前模型上停止推进。**

独立 Validation 源的重点类别 Recall：Full 的 PSK8/PSK16/QAM64/QAM256 为 **0.173/0.138/0.070/0.145**；mask 为 **0.222/0.121/0.042/0.222**。mask 对 PSK8、QAM256 的预测分别为 **1266、1295** 次，而 QAM64 为 **269** 次；训练源各类别 Recall 几乎 1。全 13 类支持数、Recall 与预测频数见 [训练与验证逐类.csv](训练与验证逐类.csv)。类别偏置发生在独立源评价，不应解释为固定的采样矩阵混淆方向。

## 数据一致性排疑

- `gate.json` 已核验三 split 的源/噪声 seed 隔离、生成顺序 169 组合各 10/2/2 个源、两路单位功率、随机不同槽及抽样 Full/MCS 逐点一致。
- 用冻结正式生成器在 train/Validation/Development 各抽首、中、末 3 个源，重新生成 Clean Full、源 UID、排序后两槽与两标签；**全部与 H5 一致**，见 [readonly_diagnosis.json](../readonly_diagnosis.json)。这是有界抽查，不声称全 2366 个源逐波形复算。
- 在 −2 dB，三 split 的两路平均功率均约 1；实测 Full 噪声功率均值分别约 **1.58495/1.58507/1.58449**，对应实测分量 SNR 均约 −2 dB。这不支持明显 train/Validation 噪声口径漂移，但不能排除其他未测的输入分布细节。
- 频率排序后的有序类别组合分布不精确：train 每组合 5–15 源，Development 的 169 种中有 **7 种未出现**（但生成顺序的 169 组合均衡）。这增加小格估计不确定性；不构成标签错位或源泄漏。训练的有效独立波形只有 1690 个，11 档噪声视图不能当作 18,590 个独立源。

## 对上一轮 A–F 的修正

1. **双信号低 SNR Full 优势：未判定。**这次 PairExact 极低、重点低 SNR 配对差区间跨零；逐路差仅为此单种子模型的探索性现象。
2. **双信号新混淆：可观察到广泛低 Recall，但不能定位物理成因。**同一 checkpoint 训练源近乎全对、独立源塌缩，表明模型记忆与泛化是主导限制。
3. **η 与额外错误：当前不可有效检验。**真实对子 η 仅 1.005–1.508，Full-only view 83 个，分层差不单调；低基准准确率进一步降低辨识力。
4. **A_C 结构感知模型：暂不设计训练。**先解决独立源泛化；否则新结构效果会被源记忆和种子波动混淆。

## 下一轮最小合同与停止条件

先做**训练源规模/泛化控制**，不做多种子 η 复验：固定历史 Coset、同一正式生成器、11 档 SNR、DualV6(80,13)、优化配置、Validation 选点、已有独立 Development 与同一训练种子；仅增加训练 split 中的独立源数量，并保留 Full/MCS 同源共噪声。生成前冻结源数与磁盘预算，检查是否与现有源重复；每种生成顺序的有序调制组合仍均衡，报告频率排序后的实际分布。该合同需要在下一轮作业启动前再次做显存/内存/磁盘、代码哈希、标签及配对复核。**本轮不启动。**

通过门槛建议事先定为：两臂 Validation 逐路 ModAcc 至少明显超过本轮 0.1665/0.1303，PairExact 至少超过 0.0395/0.0242，且 PSK8/PSK16/QAM64/QAM256 不出现近零 Recall；达不到则停止 η→CNN 关联路线，转向输入表示、网络容量/正则化、来源多样性和标签顺序的独立控制。若通过，再开展冻结 η 分层和最小多种子复验；不能在同一 Development 集上按结果选超参并仍称无偏验证。
