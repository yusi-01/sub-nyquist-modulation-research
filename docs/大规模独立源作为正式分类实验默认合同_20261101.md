# 大规模独立源作为正式分类实验默认合同（2026-11-01）

用户决定：后续用于论文主结论的分类训练与对照，使用完整的大规模独立源数据。小规模数据继续用于物理QA、代码烟测、资源估算和失败定位；其结果仅说明对应小规模条件，不外推为大规模模型性能或采样机制结论。

## 默认规模

|任务|train|Validation|Development|说明|
|---|---:|---:|---:|---|
|单信号|13000|2600|2600|每类1000/200/200独立源；11档SNR视图不计为独立源|
|双信号|16900|3380|3380|169种生成顺序组合每种100/20/20独立源；按频率排序后的组合分布另行报告|

物理与评价合同沿用当前冻结的Fs=2GHz、L=40、M=8、历史Coset、13类、同一Full域AWGN、共源共噪声、源级split隔离、−10至+10 dB步长2的开发网格。checkpoint只由Validation选择；Development只用于冻结方案的分析；Final Test不用于调参。正式论文结论需多训练种子与一次性独立Final评价。

## 已有资产与限制

服务器上历史双信号16900源H5确实存在，但仅保存形状`(185900,1024,16)`的MCS输入；历史训练为16通道Res1dNet31。它可作为历史有效性与16通道诊断证据，**不能直接提供80通道Full输入或当前DualV6(80,13)严格配对对照**。现有单信号Full训练H5为`(143000,80,1024)`，对应13000源×11档。当前双信号Full/MCS严格配对数据只有1690+追加3380训练源以及338/338验证/开发源。

若恢复双信号Full80/MCS-mask80主线，应先构建同一正式生成器下的16900/3380/3380独立源完整Full视图，并从同一Full噪声视图抽取MCS。该数据必须单独命名、预算约百GiB量级、先过源UID/哈希/标签/配对门禁，再训练；不能把历史16通道H5和新的Full80 H5拼成“严格配对”。

## 当前决策

5070源MCS-mask80相比1690源的独立源指标确实提高，但Development PairExact仍仅4.28%，APSK32 Recall仅0.70%。因此“大规模源”是正式实验的默认规模，**不等于现已证明源数量是唯一瓶颈**。下一项正式训练前仍需只读核对16/80通道输入、DualV6与Res1dNet31和标签频率排序的差异，避免在错误表示上投入完整大规模训练。该核对不改变用户关于正式实验使用大规模数据的决定。
